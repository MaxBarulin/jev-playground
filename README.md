# Jev playground

Локальная песочница для решающих моделей System One: Jev от TypeSafe через Polza.AI или любой сервер с тем же контрактом, например локальная Laya.

Jev не генерирует текст. Вы даёте текст (`state`) и именованные вопросы, модель возвращает вероятности:

| Тип | Что спрашивает | Что возвращает |
|---|---|---|
| `noul` | да/нет | `noul` — вероятность «да», 0…1 |
| `choice` | один вариант из списка | `choice`, `probabilities` по вариантам, `confidence` |
| `score` | место на упорядоченной шкале | `score` от 0 до (уровней − 1), `probabilities` по уровням, `legend`, `confidence` |

## Запуск

```bash
venv/Scripts/python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и впишите `POLZA_API_KEY`. `.env` в git не попадает.

Проверить связь с API одним запросом (стоит около 0,02 ₽):

```bash
venv/Scripts/python scripts/smoke_test.py
```

Интерфейс:

```bash
venv/Scripts/streamlit run app.py
```

Откроется http://localhost:8501.

## Что внутри интерфейса

- **Песочница.** `state` текстом или JSON, конструктор вопросов и рядом сырой JSON запроса: правка в одном месте сразу видна в другом. Пять пресетов загружаются кнопкой. Результат: карточка на каждый вопрос с графиком вероятностей, латентность, токены, стоимость, сырой ответ, запрос и curl. Ключ в curl не подставляется, вместо него переменная `$POLZA_API_KEY`.
- **Эксперименты.** «Повтор N раз» отправляет текущий запрос N раз и показывает разброс вероятностей и латентности. «A/B» сравнивает две формулировки одного вопроса на одном state.
- **Пакетный режим.** CSV или XLSX, колонка (или несколько) как state, вопросы из песочницы. Запросы идут параллельно (по умолчанию 4). Строки с уверенностью ниже порога подсвечиваются для ручной проверки. Результат выгружается в XLSX. Уверенность для `choice` и `score` — `confidence`, для `noul` — `|2·P(да) − 1|`.
- **История.** Каждый запрос и ответ пишется в `history.jsonl`. Записи можно смотреть, отправлять повторно (на текущий провайдер из сайдбара) и открывать в песочнице. Файл в `.gitignore`.

Провайдер выбирается в сайдбаре: Polza.AI или свой сервер. Для Laya из Unsloth Studio укажите `http://127.0.0.1:8888` и модель `laya`. Пишите `127.0.0.1`, а не `localhost`: на Windows `localhost` сначала пробует IPv6 и добавляет к каждому запросу около 2 секунд.

## Клиент в своих проектах

`client.py` не зависит от интерфейса, нужны только `httpx` и `pydantic`.

```python
from client import JevClient, choice, noul, score

jev = JevClient()  # ключ из переменной окружения POLZA_API_KEY
result = jev.evaluate(
    state="Кроссовки пришли не того размера, нужен обмен до субботы",
    questions={
        "is_urgent": noul("Клиент сообщает о срочной проблеме?"),
        "team": choice("Какая команда должна заняться обращением?",
                       {"returns": "Обмен и возврат", "other": None}),
    },
)
print(result.response.answers["team"].choice, result.latency_ms)
```

- `send(payload)` отправляет готовое тело запроса. `aevaluate` и `asend` — асинхронные версии.
- `asend_many(payloads, concurrency=4, on_progress=...)` отправляет пачку параллельно. Ошибка одной строки возвращается на её месте и не роняет остальные.
- Повторы: на 408, 429, 5xx и сетевых таймаутах, по умолчанию 3, паузы 1, 2 и 4 с. `Retry-After` соблюдается, если он не больше 60 с.
- До отправки `check_request` сверяет запрос с лимитами из документации. Ошибки приходят как `JevValidationError` (не отправлено) или `JevAPIError` (статус, код, `trace_id`, понятный текст).

Свой сервер: `JevClient(api_key="", base_url="http://127.0.0.1:8888", model="laya")`. Пустая строка вместо ключа нужна, чтобы клиент не взял ключ Polza из окружения.

## Контракт и лимиты Polza.AI

По документации: https://polza.ai/docs/api-reference/systemone/create.md

- `POST https://polza.ai/api/v1/systemone`, заголовок `Authorization: Bearer <ключ>`.
- Модели: `typesafe/jev` и `jev-latest` указывают на последнюю стабильную версию. Принимаются также `jev-preview` и `jev-1.13.0`. Какая версия ответила, видно в поле `model` ответа.
- Варианты задаются полем `criteria`. Для `choice` это `{ключ: описание | null | объект}`. Для `score` — список уровней по возрастанию. Для `noul` — необязательный `{"true": ..., "false": ...}`.
- Лимиты:
  - вопросов от 1 до 256;
  - вариантов в `choice` до 255;
  - уровней в `score` от 2 до 10;
  - `state` и `questions` до 400 000 символов каждый;
  - контекст модели: 32 000 токенов на state и самый длинный вопрос, 64 000 токенов на state и все вопросы вместе.
- Платятся только входные токены, плюс около 280 служебных на запрос. Поэтому выгоднее задавать все вопросы одним запросом.
- Ошибки приходят в формате `{"error": {"code", "message", "trace_id", ...}}`. 429 бывает с `Retry-After` (лимит Polza) или без него (лимит провайдера).
